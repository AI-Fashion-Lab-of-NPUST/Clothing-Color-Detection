1. EXECUTIVE SUMMARY

This report documents the architectural improvements made to a computer vision pipeline designed to detect the presence of 11 distinct color classes on segmented fashion garments. The final deployment yields a reliable System-Wide Accuracy of 77.94% and hits a critical milestone of 100% precision on true vibrant shades like Red.

2. THE BASELINE SYSTEM & PREVIOUS ARCHITECTURAL FLAWS

Initially, the system evaluated color presence using a flat, hardcoded minimum threshold constraint of 5.0% (if pct > 5.0) on pixel clusters gathered via K-Means. This baseline approach suffered from three critical issues:

A. High False-Positive Rates (Color Hallucination)

Because a minor 6% pixel presence was enough to trigger a positive label, the system constantly registered camera sensor noise, background bleed, and naturally occurring garment folds/shadows as valid fabric colors.

B. Severe Neutral Space Overlap

The model suffered from massive false-positive inflation in the Grey and Black domains. For instance, in early tests, Grey yielded a catastrophic Precision of 0.28. The model registered "Grey" nearly every time a white garment had a natural physical crease or shadow, making the metric utterly unfeasible for multi-label compliance.

C. The Inverted Axis Evaluation Bug

The original evaluation plotting script misaligned scikit-learn’s structured 2x2 matrix output. It hardcoded the True Absence indices onto the True Presence display labels, rendering an upside-down confusion matrix that masked the actual behavior of the underlying model.

3. ITERATIVE IMPROVEMENTS & ADVANCED SOLUTIONS

To achieve standard industrial-grade viability without completely rebuilding the underlying segmentation transformer, we executed a two-phased engineering intervention:

Phase 1: Fixed Thresholding & Visual Correction

• Correction: We re-mapped the confusion matrix subplots to structurally place True Presence (Positive Class) on top and True Absence (Negative Class) on the bottom, allowing for proper engineering readouts.
• Intervention: We escalated the flat rejection constraint from 5.0% to 15.0%.
• Result: This single move wiped out low-level background shadow noise and successfully boosted the Precision of Red to a perfect 1.00, while dropping macro-level false alarms. However, a strict flat threshold caused sensitive or minor color details (like Beige and Blue strings/stripes) to get clipped, hurting overall sensitivity (Recall).

Phase 2: Implementation of Dynamic Post-Processing Thresholding

Recognizing that vibrant colors and neutral colors behave completely differently under camera lenses, we abandoned the single flat threshold and engineered a Dynamic Threshold Matrix applied directly during output generation:
python
# Programmatic Dynamic Threshold Rule Matrix
if color in ["Grey", "Green", "Beige", "Blue", "Purple", "Brown"]:
    threshold = 28.0  # Strict constraint eliminates shadow/shading hallucinations
elif color in ["Black", "White", "Red", "Yellow", "Pink"]:
    threshold = 12.0  # Flexible constraint protects sensitivity on reliable shades
